## 1. 项目概述与目标

**一句话**: Windows PC 做大脑（视觉+决策），STM32F103C8T6 做脊髓（舵机执行），低成本 6 轴机械臂实现"看到方块 → 抓起来 → 放到目标位"。

**目标**:
- 抓取成功率 ≥70%（10 次中 7 次）
- XY 定位精度 ±5mm（视觉粗定位 + 红外精确认）
- 单次抓取 <15s
- 通信丢包 <1%，连续运行 ≥30min
- 总硬件成本 ≤¥100（不含机械臂本体）

**非目标**（明确不做）: 深度相机 6DoF 抓取、模仿学习、ROS2、总线舵机——见 §12 进阶路线。

## 2. 架构原则（决策依据）

| # | 原则 | 说明 |
|---|------|------|
| P1 | **PC 大脑 / MCU 脊髓** | 视觉、IK、轨迹、状态机全在 PC（Python）；STM32 只做 PWM 输出 + 红外读取 + 协议解析。参考 JetArm / DOFBOT-SE / PAROL6 同构 |
| P2 | **粗定位 + 精确认** | XY 靠视觉（±5mm），Z 轴不测量，靠红外"物理接触确认"——低成本无深度相机的关键模式 |
| P3 | **固件薄、上位机厚** | 固件只做执行与安全，算法全在上层。固件改动必须编译验证（0 Error） |
| P4 | **安全三层** | 硬件（保险丝/防反接/急停）→ 固件（限位/超时/看门狗）→ 软件（状态机超时/DRY_RUN） |
| P5 | **所有参数集中管理** | 上位机 config.py 集中所有魔术数；固件常量宏定义。禁止散落裸数字 |
| P6 | **诚实声明** | 推测值、未验证假设、半截功能必须记录（docs/project/UNIMPLEMENTED.md / 诚实声明清单），不假装完成 |

## 3. 系统架构

```
┌─────────────────────────────────────────────────────────────┐
│ 感知层    USB摄像头/DroidCam + YOLO11n（PC 推理）             │
│           + 红外对射 QT30CM ×2（触觉确认）                    │
├─────────────────────────────────────────────────────────────┤
│ 决策层    Windows PC（Python）                               │
│           vision → calibration → kinematics → trajectory    │
│           → state_machine → arm_serial                      │
├─────────────────────────────────────────────────────────────┤
│ 控制层    STM32F103C8T6（USB CDC 虚拟串口）                  │
│           协议解析 → 舵机 PWM + 红外读取 + 安全层             │
├─────────────────────────────────────────────────────────────┤
│ 执行层    6×MG996R + 6V 8A 独立电源（端子排汇流）            │
└─────────────────────────────────────────────────────────────┘
```

**数据流（一次抓取）**:
```
摄像头帧 → YOLO 检测(block, conf≥0.6) → 像素坐标
→ 四点标定单应矩阵 H → 毫米坐标 (x,y)
→ IK 解析解 → 关节角 q[6]（可达性/奇异检查）
→ S 曲线插补 + 单方向逼近消隙 → 逐帧 M<n> angle 命令
→ STM32 PWM 输出 → 舵机运动
→ 下降 → 红外遮断（IR=1）→ 夹爪闭合 → 抬升 → 放置 → 回 HOME
```

## 4. 关键决策记录（ADR）

| # | 决策 | 选择 | 备选与否决理由 |
|---|------|------|----------------|
| ADR-1 | 控制架构 | PC 大脑 / MCU 脊髓 | MCU 全做：浮点慢、开发慢、无视觉能力 ❌ |
| ADR-2 | 通信 | USB CDC 虚拟串口 | UART 需模块；蓝牙 20ms 延迟；WiFi 过度设计 |
| ADR-3 | IK 选型 | 解析解（atan2+余弦定理） | 5 轴有效（J5 固定 90°）、几何规整；数值 IK（IKPy/TRAC-IK）过度 |
| ADR-4 | Z 轴确认 | 红外物理接触（不测量） | 深度相机超预算；木块对 940nm 100% 遮挡 |
| ADR-5 | 消隙 | 单方向逼近（过冲 15°） | AR4/SO-100/GELLO 验证；MG996 虚位 ±3~8° |
| ADR-6 | 轨迹 | S 曲线 + 20ms 插补（上位机） | 与舵机 50Hz 刷新对齐；直接跳变 = 抖动 |
| ADR-7 | 供电 | 6V 8A 独立 + 共地 + 端子排 + 大电容 | USB 500mA 带不动 15A 瞬态 |
| ADR-8 | 红外器件 | QT30CM 成品计数模块 | 自带限流/整形，省 160Ω/10kΩ；散件需自搭电路 |
| ADR-9 | 主控板 | 标准 Blue Pill（无 CH340） | USB 直连 PA11/12，USB CDC 固件零改动；CH340 版占 USART1 与舵机冲突 |
| ADR-10 | 固件安全 | 限位钳位 + 10s 超时 + IWDG + H/E 命令 | 手册 §十三 Layer 2 要求（已实现，见 docs/project/UNIMPLEMENTED） |
| ADR-11 | 视觉标定 | 4 点透视单应矩阵（eye-to-hand） | 3 点仿射精度不足；1080P@40cm ~0.3mm/px |
| ADR-12 | 工具链 | Keil MDK-Lite（HAL 库）+ Python 3.10 + Ultralytics | MDK-Lite 32KB 限制（当前 16.97KB 余量足） |

## 5. 固件架构（STM32F103C8T6）

**现状**（编译通过 16.97KB，0 Error）:
```
Core/Src/main.c              ← 主循环 + 时钟(8M×PLL9=72M→USB 48M) + TIM1/TIM2 PWM + USB 初始化
       usbd_conf.c           ← USB LL 底层回调 + HAL_PCD_MspInit（新版库 API）
       usbd_desc.c           ← 描述符（VID 0x0483 / PID 0x5740）
       usbd_cdc_interface.c  ← CDC 环形缓冲(512B) + 命令解析
       stm32f1xx_it.c        ← USB_LP_CAN1_RX0_IRQHandler
       stm32f1xx_hal_msp.c   ← TIM1/TIM2 时钟 + GPIO AF
```

**引脚映射（勿改）**: 舵机1-6 = PA8/PA9/PA10(TIM1_CH1-3) + PA0/PA1/PA2(TIM2_CH1-3)；红外 = PB12/PB13（输入上拉，遮挡=0）；USB = PA11/PA12（**禁做 PWM**）；SWD = PA13/PA14。

**协议**（CRLF 结尾 ASCII 行）: `M<n> <angle>` / `MALL <angle>` / `I` / `S` / `H` / `E`；回 `OK` / `IR1=x IR2=y` / `S1=.. S6=..` / `ERR`。

**安全层（v1.1 已实现，review-hw 两轮审查通过）**: 关节限位钳位（M 回显 clamp 后实际值）、10s 无命令超时（PWM 停止→舵机松脱）、USB 断开停 PWM + 清残留命令、IWDG ~2s、H/E 命令、急停/超时/断开三状态门控。

**连杆参数表**（几何解析解用，非标准 DH；**推测值，待实测标定**）:
| 参数 | 值 | 说明 |
|------|-----|------|
| L1 | 50mm | 底座高度（J1 轴心到 J2 轴心） |
| L2 | 120mm | 大臂长度（J2 到 J3） |
| L3 | 100mm | 小臂长度（J3 到 J4） |
| J5 | 固定 90° | 腕旋转固定，5 轴有效 |
| 坐标系 | 右手系，Z 向上 | 桌面平面 XY，J1 轴心为原点 |

## 6. 上位机架构（pc/，位于固件工程内）

```
pc/
├── config.py        ← 所有参数集中（单位：度/mm/ms；JOINT_LIMITS；轨迹/安全/视觉参数）
├── vision.py        ← YOLO 推理（预热 1 帧、conf=0.6、iou=0.45、max_det=1、中文路径 np.fromfile）
├── calibration.py   ← 四点标定（getPerspectiveTransform → H；边缘偏差大先 undistort）
├── kinematics.py    ← IK 解析解 + FK 验证闭环（FK(IK(T))≈T）+ 可达性/奇异检查
├── trajectory.py    ← S 曲线插补（max_vel=30°/s, acc=15°/s², dt=20ms）+ 单方向逼近 + 软启动
├── arm_serial.py    ← pyserial（timeout=0.1、等 OK 再发、接收线程 deque）
├── ir_sensor.py     ← 红外读取 + 去抖（3/5 判定）
├── state_machine.py ← 抓取状态机（IDLE→APPROACH→DESCEND→GRIP→TRANSPORT→RELEASE→HOME；超时→ERROR→安全回退；DRY_RUN）
└── main.py          ← 主流程编排
```

**状态机铁律**: 每状态有超时；每入口记日志；ERROR 先抬 Z 再回 HOME；禁止 time.sleep 长等待（非阻塞计时器）；下降 Z 单调递减；夹爪闭合后等 200ms 再抬升。

**上位机回显铁律（联调生死线）**: 固件对 `M<n>` 回显 **clamp 后的实际角度**。`arm_serial.py` **必须解析回显值并调用 `kinematics.update_joint_state(actual)` 更新内部关节状态**，严禁忽略回显。若请求角度与回显偏差 >5°，上位机报 `WARNING: Joint limit mismatch` 并暂停。否则虚拟角度与物理角度脱节，3~5 次后 IK 模型漂移，臂越走越歪。

**IK 无解回退策略**: IK 不可达/奇异时，状态机转 `ERROR` → 声光报警 → 回 `HOME`，**绝不盲抓**（不发 0 角度、不死循环）。

## 7. 硬件架构

```
6V 8A电源(圆头) ──DC母头线(5.5×2.1, 10A)── [PTC 8A自恢复] ── 端子排红排(6V)/黑排(GND)
                                                          │ 短接片并联
                                                          ├── 6×MG996 红/黑
                                                          ├── 10000μF + 470μF×4 + 100nF×10+
电脑USB ──→ Blue Pill（供电+USB CDC）── GND ──→ 黑排（共地！）
红外 QT30CM: VCC→5V引脚 / GND→共地 / OUT→PB12/13（严禁接 6V）
舵机信号: PA8/9/10+PA0/1/2 ──100Ω── 舵机橙线
```

**铁律**: 共地必须；舵机电源严禁进 STM32 3.3V/5V；信号线串 100Ω；信号线与电源线间距 >2cm；软启动逐个使能（200ms 间隔）。

**过流保护选型**: 8A PTC 自恢复 ×2（串 6V 正极，过热断开自动恢复）。3A 太小——6 舵机同时运动电流可超 3A 会误动作；PTC 只保护短路，正常工况不动作。**到货实测 QT30CM 输出类型**（推挽则免外部上拉，开漏则加 4.7kΩ 外部上拉）。

## 8. 安全体系（三层）

| 层 | 措施 | 状态 |
|----|------|------|
| L1 硬件 | 8A PTC 自恢复（舵机电源正极）、防反接二极管、急停按钮（断 6V） | 待采购/待装 |
| L2 固件 | 关节限位钳位、10s 无命令超时、USB 断开停 PWM + 清残留命令、IWDG ~2s、H/E 命令、三状态门控 | **✅ 已实现（v1.1，审查通过）** |
| L3 软件 | 状态机超时、可达性检查、IK 无解回退、速度/加速度限制、DRY_RUN、全量日志 | 待建（Phase C） |

**超时行为定义**: 10s 无命令 → **停止全部 PWM → 舵机松脱 → 臂因重力下垂（无动力安全姿态）**。收到任意新命令自动恢复。注意：松脱 ≠ 保持——臂会下垂，上位机恢复后必须先 `H` 回中位再继续（或从当前实际姿态重新规划）。

## 1. 背景与判定

2026-08-24 架构审查结论（已逐条对照代码验证）：

> **设计/分层：优秀的 hobby 架构。运行时/可靠性：未合格——"纸面很美、实机脆弱"。**

四个结构性问题（全部确认属实）：

| # | 问题 | 证据 |
|---|------|------|
| S1 | 运动关键路径在非实时 PC + 阻塞串口上 | 轨迹每 20ms 发 6 条 M 走串口往返；IWDG/超时本质是给不可信链路打补丁 |
| S2 | 双管线未收敛 | `run_grasp` 内 if/else 同时维护像素伺服路线与旧 mm 路线；calibration.py 成死代码 |
| S3 | "闭环"宣称只覆盖逼近段 | TRANSPORT→PLACE 用未实测 L1/L2/L3 做毫米开环 IK，误差几十 mm 级 |
| S4 | 状态机为命令式巨型函数 | ~270 行 if/break/continue 嵌套，回退分支难 trace、不可单测 |

## 2. 升级方案（四项改动）

### 改动①（核心）：运动执行权下沉 MCU —— MOVE/DONE 协议

**原则修订**：P1"PC 大脑/MCU 脊髓"从语义层切分升级为**时间层切分**——感知/对齐/决策留 PC（有反馈的地方），纯机械运动的**时间轴**归 MCU。

**协议**：

```
MOVE <j1> <j2> <j3> <j4> <j5> <j6>   # 六轴目标角（整数°），MCU 限速斜坡逼近
DONE                                  # 查询 → "BUSY" / "DONE"
```

- 固件：把现有 `Servo_RampStep`（当前仅服务 H 命令）泛化为六轴通用斜坡器。
- 上位机：`Trajectory._exec_point` 的"每 20ms 刷 6 条 M + 忙等"替换为"发 MOVE → 轮询 DONE → 查 S 对账"。
- 收益：串口流量降一个数量级；Windows 卡顿/掉拍时臂按最后一条 MOVE 稳定走完，不再瘫掉；固件超时/限位从补丁变成有意义的最终裁判。

### 改动②：TRANSPORT 诚实降级（B 默认）+ 可选视觉放置（A 后置）

- **B（默认，立即做）**：文档与注释明确声明 PLACE 为开环近似，误差级 = 齿轮间隙(±3~8°) + IK 未校准连杆，预期 ±2~3cm。
- **A（可选，实测后决定）**：抬升到 SAFE_Z 后对放置区复用 `_servo_align` 做像素伺服。是否需要由实机测量开环放置误差后投票（YAGNI）。

### 改动③：状态机轻重构（排在①之后）

不做 FSM 框架（7 个状态不配用框架）。轻量版：`run_grasp` 拆成 `_do_search()/_do_align()/_do_descend()/...`，每状态返回 `(next_state, data)`，dispatch 循环串联。控制流扁平化、状态可单独 DRY_RUN 测试。

**必须排在①之后**：①落地后状态机变薄、部分状态合并，先改会返工两遍。

### 改动④：删除旧管线（随时可做）

保留像素伺服为主管线。`calibration.py`、`CALIB_PTS_*`、`DROIDCAM_URL`、旧 mm 路线 else 分支整块挪 `legacy/` 单独入口。

## 3. 施工修正案（本地复核补充，外部方案未覆盖的 4 个坑）

| # | 坑 | 修正案 |
|---|-----|--------|
| A | **MOVE 打破回显铁律现有实现**：clamp 发生在斜坡过程中，无法即时回显实际值 | 显式重定义记账：MOVE 立即回 `OK MOVE`（接受）；BUSY 期间 `joint_state` 标记为"趋向目标"；DONE 后查 S 对账校准。漂移检测窗口变粗但频次也降，净效果可接受 |
| B | **M 与 MOVE 共存语义未定义**：斜坡中途收到 M 会灵异 | GRIP/J5 夹爪保留 M；其余运动全走 MOVE；**M 到达时取消进行中的斜坡** |
| C | **软启动浪涌时序被废**：现设计靠 lazy start + M1..M6 各隔 200ms 错开六轴浪涌；MOVE 六轴同起 = 峰值 2.5A×6=15A > 电源 8A | MOVE 内部各轴错开 50~100ms 起步，或全局限速再压一档 |
| D | **超时语义需重定义**：段式控制下命令间隔天然变长（视觉推理耗时），15s 超时会误触发 | DONE 查询同样刷新 `last_cmd_tick`；或改为"BUSY 超 X 秒无进展才断电" |

工程量修正：固件非"60 行几乎直接用"，实际约 100~150 行（可设目标/可取消/DONE 检测/错峰起步），仍是一个周末的量。

## 4. 明确不做的事（防过度工程）

- 不上 RTOS / 多线程 / 共享内存状态机——瓶颈是"时间由谁控制"，不是并发。
- 不把视觉推理搬进 MCU——F103 跑不动 YOLO，此路不通。
- 不为消隙/S 曲线造更强运动学模型——hobby 误差级下现有方案够用，性价比最低。

## 6. 验收标准

- [ ] Windows 人为卡顿 500ms（调试器断点模拟）：臂不停、不瘫、不触发超时断电
- [ ] 单次 TRANSPORT 串口命令数 ≤ 10 条（现状约数百条）
- [ ] 回显铁律在新协议下成立：DONE 后 S 查询值与目标偏差 >5° 必报警
- [ ] 六轴同时 MOVE 启动时电源无塌压（示波器/万用表监测 6V 母线）
